# AMK Data Visualization

Актуальное состояние: **16 июля 2026 года**.

`AMK-Data-Visualization` — новая WinUI 3 / .NET 10 реализация приложения
`Amk-Horizon-New-Chart`. Цель переноса — сохранить поведение, форматы данных и
расчётные контракты старого Win32/C++ приложения, одновременно разделив код на
модули и обновив визуальное оформление.

Старый проект остаётся источником истины по поведению:

`C:\Users\Admin\Desktop\Amk-Horizon-New-Chart`

## Что уже работает

- загрузка `.bin`, `.biv` и `.DEV` в canonical `GpToolData`;
- `ToolDataRepository`, metadata/capabilities и экспорт диапазонов;
- один или два графика, linked/independent источник Graph 2;
- несколько кривых, левая и правая Y-оси, X по кадрам или температуре;
- сетка, legacy nice-step, целые подписи кадров и фиксированный числовой формат;
- немодальное окно «Схема прибора» для Graph 1 и Graph 2;
- комбинированный выбор T1..T5, R1/R2 и молчащих каналов;
- полный набор быстрых пресетов, перенесённый на текущем этапе;
- legacy-совместимые легенды быстрых и комбинированных конфигураций;
- независимые viewport-состояния Graph 1/Graph 2: X Range, drag-zoom,
  пошаговый undo/reset zoom, X/Y-scroll и динамическое окно `Поток` с
  автомасштабом и Y-only zoom/scroll;
- автоматический 5%-й отступ Y-диапазона от верхней и нижней границ графика;
- единое пользовательское имя «Визуализация данных» для Visual Studio,
  заголовка окна, исполняемого файла и установленного приложения;
- фирменная иконка с осями X/Y, двумя кривыми и эмблемой компании AMK в правом
  верхнем углу во всех размерах WinUI, исполняемом файле, окне, ярлыках и
  установщике;
- all-users Inno Setup installer: установка в Program Files, регистрация в
  «Установленных приложениях», отдельный выбор общих ярлыков меню «Пуск» и
  рабочего стола;
- ручная и отложенная фоновая проверка обновлений; новая версия загружается как
  полный установщик, проверяется как PE и, если опубликована третья строка
  `data-visualization-version.txt`, по SHA-256;
- просмотр выбранного участка, canonical `.bin`-экспорт и вырезание участка из
  текущего файла либо в отдельную копию с сохранением физического формата;
- поиск COM-портов, подключение 125000/8N1, polling, CRC16 и чтение команд
  `0x11`, `0x13`, `0x16`; обычные приборы используют length-framed transport,
  `Картограф LWD 4tx` — фиксированный transport `LOOP_NEXT`;
- запись live-кадров в новый canonical `.bin` и дозапись существующего файла;
  папка по умолчанию — автоматически создаваемая `AMK_Data` на рабочем столе,
  а выбранный пользователем другой путь сохраняется между запусками;
- окно «Подключение к прибору» и сохранение его параметров в `%LOCALAPPDATA%`.
- окно «МЕТРОЛОГИЯ» с чтением/записью зонда, 240-байтовыми файлами и
  автокалибровкой воздуха;
- прибор `Картограф` в режиме `LWD 4tx`: сигнатура с типом `Картограф` и
  четырьмя передатчиками использует общий 240-байтовый `GP_TOOL_DATA` и
  доступна при чтении файлов и live-опросе независимо от модификации; live-ответ
  читается как `[CMD][242 байта payload][CRC16]`, структура начинается после
  двух служебных байтов, нулевой CRC кадра разрешён с проверкой сигнатуры;
- амплитуды `Картограф LWD 4tx` нормализуются из передаваемого прибором
  Q12-масштаба в общий LWD-контракт `mV`; это одинаково применяется к R1/R2 и
  молчащим каналам во всех быстрых и комбинированных конфигурациях, при этом
  сырые 240-байтовые кадры в файлах не изменяются;
- подробный журнал COM-обмена `CartographLwd4Tx.log` создаётся в корне проекта
  при первой попытке подключения и содержит выбор протокола, TX/RX, размеры,
  CRC, таймауты, декодированную сигнатуру и причины отклонения кадров;
- вычисление УЭС и симметризованных фаз на компьютере по считанной метрологии,
  включая legacy-матрицы 3/4/5Tx;
- выверенная владельцем русская компоновка метрологии: штатные WinUI ComboBox,
  типы `Автономный` / `LWD` / `Картограф`, L/F только для чтения по умолчанию,
  смысловые подписи воздушных поправок и выровненные поля сигнатуры/палитры.

Обычный режим `Картограф 5tx` имеет другую структуру данных и этой canonical-
веткой намеренно не принимается.

## Что пока не завершено

- немодальное пользовательское окно журнала обмена (файловая диагностика уже
  реализована);
- crosshair, координаты курсора и LOD/cache;
- append-варианты range/cut и перенос sidecar-сегментов при файловых операциях;
- заметки, sidecar-сегменты, конструктор файлов;
- reporting;
- публикация и code signing релизного установщика, а также ручная проверка
  установки/удаления и полного цикла автообновления;
- полная ручная parity-проверка на наборе реальных файлов и физическом приборе.

Проект `AMK.DataVisualization.Reporting` пока остаётся архитектурным контейнером
без прикладной реализации.

## Сборка

Требуется Windows и установленный .NET 10 SDK.

```powershell
cd C:\Users\Admin\Desktop\AMK-Data-Visualization
dotnet build .\AMK-Data-Visualization.slnx -c Debug -p:Platform=x64 --no-restore
```

Приложение unpackaged/self-contained, основной исполняемый файл после Debug-сборки:

```text
AMK-Data-Visualization\bin\x64\Debug\net10.0-windows10.0.26100.0\win-x64\DataVisualization.exe
```

Установщик собирается без запуска приложения:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Build-Installer.ps1
```

Результат и порядок публикации обновлений описаны в
[`installer/README.md`](installer/README.md).

Автоматизированных тестовых проектов в решении нет. Успешная сборка подтверждает
компиляцию, но не заменяет ручную проверку UI, реальных файлов и COM-прибора.

Последняя подтверждённая проверка: решение собирается в `Debug x64` без
предупреждений и ошибок; self-contained `Release x64` publish содержит
обязательные `DataVisualization.pri` и WinUI `*.xbf`, после чего компиляция
Inno Setup также проходит. Установщик версии `0.1.1` и приложение после этого
исправления не запускались по просьбе владельца. Реальный live-опрос сигнатуры `0x00055349` подтвердил
приём и запись кадров `Картограф`, 4 Tx; сохранённый кадр также подтвердил
Q12-масштаб амплитуд и коэффициент нормализации `1 / 4096`. Ручная проверка
отображения после нормализации и численный parity `FromSonde` / `FromComputer`
остаются за владельцем.
