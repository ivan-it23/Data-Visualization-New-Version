# AMK Data Visualization — актуальный снимок сессии

Последнее обновление: **2026-07-16**.

## Назначение

Этот файл — краткий оперативный handoff. Он описывает текущее состояние
рабочего дерева, последние принятые решения, границы проверки и ближайшую точку
продолжения. Общий маршрут находится в `MIGRATION_PLAN.md`, подробные контракты
и исходные C++-якоря — в `AMK_DATA_VISUALIZATION_MIGRATION_HANDOFF.md`.

## Текущая цель проекта

Перенести поведение `Amk-Horizon-New-Chart` в WinUI 3 / .NET 10 без изменения
бинарных форматов, расчётной семантики и пользовательских сценариев. Допускается
современная Fluent-отделка, но структура окон и логика берутся из старого
приложения.

## Состояние решения

- платформа: WinUI 3, `.NET 10`, `x64`;
- модель поставки: unpackaged, Windows App SDK self-contained;
- решение: `AMK-Data-Visualization.slnx`;
- автоматизированные тестовые проекты удалены по просьбе владельца;
- функциональная проверка выполняется владельцем вручную на реальных файлах и
  физическом приборе;
- последний build: `Debug x64`, `0 warnings`, `0 errors`.

В рабочем дереве находятся незакоммиченные изменения transport/logging для
`Картограф LWD 4tx`, настройки папки записи и сопутствующей документации. Их
нельзя отбрасывать; в новой сессии обязательно выполнить `git status --short`.

## Реализовано

### Core и IO

- `GpToolData` и `MetrologyData` с размером 240 байт и явной binary layout-моделью;
- capability-aware `ToolRecordMetadata`, `ParsedToolFrame`, adapter registry и
  semantic access-view;
- `Картограф` в режиме `LWD 4tx` распознаётся по типу и 4 Tx в signature без
  привязки к модификации, использует canonical `GpToolData` и не открывает T5;
  стандартный `Картограф 5tx` с другой структурой не принимается;
- его активные и молчащие амплитуды приводятся из Q12 к тому же `mV`-контракту,
  что обычный LWD, через capability `AmplitudeScale = 1 / 4096`; фазовые поля,
  УЭС и температура дополнительного масштабирования не получают;
- чтение `.bin/.biv` с кадром 240 байт;
- чтение `.DEV` с физическим кадром 251 байт и payload offset 11;
- stateful `ToolDataRepository`, `DataVersion`, records/metadata и имя файла;
- анализ metadata диапазонов;
- canonical `SaveDataRange` и сохранение исходной физической формы при
  `SaveFileExcludingRange`.

### Charting

- aligned multi-series расчёт для:
  - разности фаз;
  - отношения амплитуд;
  - амплитуд R1/R2;
  - phase/rho SMT, считанных из canonical данных;
  - амплитуд и разности фаз молчащего режима;
  - температуры;
- `CurveDefinition`, `ChartConfiguration`, группировка по двум Y-осям;
- независимые конфигурации Graph 1 и Graph 2;
- X по номеру кадра или температуре;
- grid, legacy nice-step, ноль как `0`, целые подписи кадров и отсутствие
  экспоненциального формата;
- компактная легенда пресета и комбинированная легенда с общей категорией на
  ось и разделителем `|` между левой и правой группами.

### Главное окно и Graph 2

- shell повторяет порядок старого приложения: верхнее меню, компактные панели,
  графики и статусная строка;
- двойной режим показывает Graph 2;
- Graph 2 работает в `Стандартном режиме` от repository Graph 1 или использует
  собственный repository в режиме `Отдельный файл`;
- смена режима Graph 2 не очищает Graph 1 и не удаляет ранее загруженный
  независимый источник Graph 2;
- live-кадры добавляются в primary repository и обновляют связанные графики.

### Окно «Схема прибора»

- немодальное отдельное окно для Graph 1/Graph 2;
- повторное открытие восстанавливает существующее окно;
- окно имеет собственную кнопку панели задач и иконки главного приложения;
- capability-aware T1..T5, R1/R2 и «Молч. R1/R2»;
- выбранные элементы выделяются только жёлтой рамкой;
- комбинированные конфигурации и legacy-проверки несовместимого выбора;
- частоты 400/2000 кГц;
- X по номеру кадра или температуре;
- быстрые пресеты:
  - `Амплитуды R1`;
  - `Амплитуды R2`;
  - `Отн. ампл.`;
  - `Разн. фаз`;
  - УЭС на приборе/компьютере;
  - симметричные фазы на приборе/компьютере;
  - `Ампл. молч.`;
  - `Разн. фаз молч.`;
  - `Температура`;
- актуальная компоновка подтверждена владельцем:
  - заголовок «Схема прибора» центрирован;
  - блоки кривых и быстрых пресетов имеют равную ширину;
  - частота выровнена слева, правая граница X-axis совпадает с `Амплитуды R2`;
  - `Применить` и `Отмена` находятся в раздельных равных колонках и не
    пересекаются при DPI-масштабировании;
  - `Температура` занимает всю ширину области быстрых пресетов;
  - красная диагностическая подпись удалена, но недопустимая конфигурация всё
    ещё блокирует `Применить`.

### COM и окно подключения

- поиск доступных COM-портов;
- transport 125000/8N1, protocol-specific DTR/RTS, таймауты и автоматическое
  переподключение;
- обычный пакет `[CMD:1][LEN:2][PAYLOAD][CRC16:2]` и fixed-length пакет
  `LOOP_NEXT` `[CMD:1][PAYLOAD:N][CRC16:2]` для `Картограф LWD 4tx`;
- реализованы чтения `0x11` (кадр), `0x13` (метрология), `0x16` (signature);
- polling с интервалом 500–30000 мс;
- создание canonical `.bin` и дозапись существующего файла;
- если пользователь не выбирал путь, используется автоматически создаваемая
  папка `AMK_Data` в системной папке рабочего стола;
  выбранная пользователем папка сохраняется и повторно используется при
  следующих запусках;
- параметры хранятся в
  `%LOCALAPPDATA%\AMK-Data-Visualization\connection-settings.json`;
- пункт «Настройки подключения» открывает окно одним кликом без промежуточного
  flyout;
- окно повторяет старую структуру: COM-порт, статус, запись в файл, таймер,
  `Подключить`/`Отключить`/`Закрыть`;
- текущий фиксированный размер окна: 600×680;
- визуальная структура окна подтверждена владельцем.
- при первой попытке подключения в корне проекта создаётся
  `CartographLwd4Tx.log`; журнал содержит TX/RX, chunks, длины, CRC, таймауты,
  декодирование signature, выбранный transport и причины отклонения кадров;

### Метрология и вычисления на компьютере

- `MetrologyData` точно соответствует 240-байтовому C++-контракту;
- `MetrologySession` хранит данные, считанные из зонда или файла;
- окно «МЕТРОЛОГИЯ» повторяет координатную схему старого диалога: геометрия,
  AIR/MIN, signature, идентификация и исходный ряд команд;
- окно имеет плотную DPI-aware компоновку без обрезания нижних команд и
  русские пользовательские подписи;
- поля `Air_zz` и `Air_zz_amt` подписаны по фактическому назначению как
  «Поправка фазы» и «Порог амплитуды»; заголовки групп визуально выделены;
- поля геометрии L1/L2 и частот F1/F2 по умолчанию доступны только для чтения;
  расположенный под подписью F2 установленный флажок «L/F только для чтения»
  фиксирует это состояние, а его снятие разрешает изменение; сигнатура выровнена
  по внешним границам полей порога амплитуды, а правая граница палитры совпадает
  с началом сигнатуры;
- элементы идентификации используют штатные WinUI `ComboBox` без переопределения
  высоты и внутренних отступов, по образцу окна `LOOP_NEXT`; списки типов,
  числа передатчиков, модификаций и R1 отображаются полностью;
- поле «Тип прибора» содержит `Автономный`, `LWD`, `Картограф`, а выбранные тип
  и число передатчиков сохраняются в signature;
- реализованы чтение и верифицированная запись метрологии (`0x13`); selected key
  (`0x17`) и автокалибровка воздуха (`0x1a`) относятся к обычному length-framed
  transport, а в legacy-ветке не отправляются без подтверждённого контракта;
- live-кадры `Картограф -> LWD-4TX` допускают нулевой CRC только в этой ветке,
  после чего обязательно проверяется совпадение signature; ответ читается как
  фиксированный payload 242 байта, canonical структура начинается со смещения 2;
- критерий legacy-маршрута — только тип `Картограф` и 4 Tx из signature;
  модификация не используется (фактический тестовый прибор `LOOP_NEXT` имеет
  signature `0x00055349`, tool code `349`, modification `9`);
- файл метрологии читается и сохраняется как ровно 240 байт;
- перенесены матрицы 3/4/5Tx, AIR-поправка, `SIGNAL` и обратный расчёт УЭС;
- режимы УЭС/фазы «на компьютере» блокируются до чтения метрологии;
- при несовпадении signature расчёт сохраняет fallback к данным зонда;
- UI-путь «Метрология» → отдельное окно проверен на реальном запуске;
- расчётная smoke-проверка и статический прогон фактической сигнатуры
  `0x00055349` прошли; новый transport ещё не проверен повторно с физическим
  прибором в этом приложении;
- итоговое окно имеет базовый размер 980×642 и DPI-aware минимальную клиентскую
  область 964×604;
- последние runtime-проверки подтвердили:
  - списки ComboBox: тип 3/3, передатчики 3/3, модификация 9/9, R1 2/2;
  - установленный по умолчанию `L/F только для чтения` блокирует 12/12 полей;
  - снятие флажка разблокирует 12/12 полей, повторная установка снова блокирует;
  - левая/правая границы сигнатуры совпадают с внешними границами полей
    `Порог амплитуды F1/F2`, а палитра заканчивается в начале сигнатуры;
- владелец подтвердил, что проблема обрезания значений ComboBox устранена.

## Реализовано частично или является заглушкой

- `AMK.DataVisualization.Reporting` пока содержит только `.csproj`;
- Graph 1/Graph 2 имеют независимые X Range, drag-zoom, пошаговый undo/reset
  zoom, X/Y-scroll и `Поток` с автомасштабом выбранного X-окна;
- автоматический Y-range использует 5%-й отступ, X-scroll работает для drag-zoom
  и диапазона из полей, Y-scroll — для пользовательского Y-zoom, включая режим
  `Поток`, где изменение X отключено; standalone WinUI-скроллбары принудительно
  удерживаются в видимом desktop-состоянии `MouseIndicator`; при перемещении
  X-окна ручной Y-range освобождается и обе Y-оси автоматически подгоняются под
  min/max кривых нового видимого участка;
- Graph 1 сохраняет выбранный участок в canonical `.bin` и вырезает его из
  текущего файла либо сохраняет копию без участка;
- append-варианты range/cut и перенос sidecar-сегментов пока не перенесены;
- cursor-поля остаются без crosshair-логики;
- controls заметок присутствуют визуально, но notes storage/rendering/hit-test
  не перенесены;
- пункты меню `Конструктор файлов`, `Логи`,
  `Проверить обновления`, `Документация` в основном являются заглушками.

## Что требует ручной проверки

### Реальные файлы

- загрузка `.bin`, `.biv`, `.DEV` через WinUI picker;
- все пресеты Graph 1 и Graph 2 на одинаковом контрольном файле;
- комбинированные конфигурации с одной и двумя Y-осями;
- подписи легенды, сетка и числовые шкалы;
- X по температуре;
- capability-aware доступность T1..T5;
- linked/independent Graph 2 с двумя разными файлами;
- range export и cut range.

### Физический прибор

- подключение и отключение;
- чтение signature и метрологии;
- получение кадров, пауза и возобновление polling;
- восстановление после временного сбоя порта;
- создание нового `.bin`;
- создание и использование `Desktop\AMK_Data` по умолчанию, а также повторное
  использование выбранной вручную папки после перезапуска;
- дозапись существующего `.bin`;
- режим «Показывать весь файл» при дозаписи.
- чтение, запись и повторная верификация 240-байтовой метрологии;
- автокалибровка воздуха и последующее перечитывание метрологии;
- совпадение УЭС/симметризованных фаз со старым приложением на тех же данных;
- ручная проверка всех быстрых и комбинированных пресетов на записанном и live-
  потоке `Картограф -> LWD-4TX` после Q12-нормализации амплитуд.

Указанные пункты не следует помечать выполненными только по результату сборки
или UI Automation: для них нужны реальные файлы либо физический прибор.

## Решения, которые нельзя потерять

- Старый C++ проект — источник истины; улучшения поведения обсуждаются отдельно
  от переноса.
- `Core` владеет binary layout и adapter-driven parsing.
- `IO` читает контейнеры, но не дублирует расшифровку canonical payload.
- Graph 1 и Graph 2 имеют независимые `ChartConfiguration`.
- Graph 2 получает repository только через `ChartWorkspace`.
- Окно схемы немодальное и хранит отдельную незавершённую editor-сессию для
  каждого графика.
- Автоматизированные тесты не восстанавливать без прямого запроса владельца.
- Build success не называть runtime- или parity-проверкой.

## Как начать новую сессию

1. Открыть `C:\Users\Admin\Desktop\AMK-Data-Visualization`.
2. Прочитать `AMK_DATA_VISUALIZATION_MIGRATION_HANDOFF.md` полностью.
3. Прочитать этот файл и нужный этап `MIGRATION_PLAN.md`.
4. Выполнить `git status --short` и не затирать чужие изменения.
5. Перед новым переносом найти соответствующий C++-контракт в
   `C:\Users\Admin\Desktop\Amk-Horizon-New-Chart`.
6. После WinUI-изменений собрать решение и проверить реальный запуск; после
   расчётных/COM-изменений отдельно зафиксировать, что проверено только кодом,
   что runtime, а что parity.
