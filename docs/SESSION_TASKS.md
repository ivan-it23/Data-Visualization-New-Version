# AMK Data Visualization — актуальный снимок сессии

Последнее обновление: **2026-07-14**.

## Назначение

Этот файл — краткий оперативный handoff. Он описывает текущее состояние
рабочего дерева, последние принятые решения, границы проверки и ближайшую точку
продолжения. Общий маршрут находится в `MIGRATION_PLAN.md`, подробные контракты
и исходные C++-якоря — в `AMK_DATA_VISUALIZATION_MIGRATION_HANDOFF.md`.

## Текущая цель проекта

Перенести поведение `Amk-Horizon-New-Chart` в WinUI 3 / .NET 10 без изменения
бинарных форматов, расчётной семантики и пользовательских сценариев. Допускается
современная Fluent-отделка, но структура окон и логика берутся из старого
приложения.

## Состояние решения

- платформа: WinUI 3, `.NET 10`, `x64`;
- модель поставки: unpackaged, Windows App SDK self-contained;
- решение: `AMK-Data-Visualization.slnx`;
- автоматизированные тестовые проекты удалены по просьбе владельца;
- функциональная проверка выполняется владельцем вручную на реальных файлах и
  физическом приборе;
- последний build: `Debug x64`, `0 warnings`, `0 errors`.

## Реализовано

### Core и IO

- `GpToolData` и `MetrologyData` с размером 240 байт и явной binary layout-моделью;
- capability-aware `ToolRecordMetadata`, `ParsedToolFrame`, adapter registry и
  semantic access-view;
- чтение `.bin/.biv` с кадром 240 байт;
- чтение `.DEV` с физическим кадром 251 байт и payload offset 11;
- stateful `ToolDataRepository`, `DataVersion`, records/metadata и имя файла;
- анализ metadata диапазонов;
- canonical `SaveDataRange` и сохранение исходной физической формы при
  `SaveFileExcludingRange`.

### Charting

- aligned multi-series расчёт для:
  - разности фаз;
  - отношения амплитуд;
  - амплитуд R1/R2;
  - phase/rho SMT, считанных из canonical данных;
  - амплитуд и разности фаз молчащего режима;
  - температуры;
- `CurveDefinition`, `ChartConfiguration`, группировка по двум Y-осям;
- независимые конфигурации Graph 1 и Graph 2;
- X по номеру кадра или температуре;
- grid, legacy nice-step, ноль как `0`, целые подписи кадров и отсутствие
  экспоненциального формата;
- компактная легенда пресета и комбинированная легенда с общей категорией на
  ось и разделителем `|` между левой и правой группами.

### Главное окно и Graph 2

- shell повторяет порядок старого приложения: верхнее меню, компактные панели,
  графики и статусная строка;
- двойной режим показывает Graph 2;
- Graph 2 работает в `Стандартном режиме` от repository Graph 1 или использует
  собственный repository в режиме `Отдельный файл`;
- смена режима Graph 2 не очищает Graph 1 и не удаляет ранее загруженный
  независимый источник Graph 2;
- live-кадры добавляются в primary repository и обновляют связанные графики.

### Окно «Схема прибора»

- немодальное отдельное окно для Graph 1/Graph 2;
- повторное открытие восстанавливает существующее окно;
- окно имеет собственную кнопку панели задач и иконки главного приложения;
- capability-aware T1..T5, R1/R2 и «Молч. R1/R2»;
- выбранные элементы выделяются только жёлтой рамкой;
- комбинированные конфигурации и legacy-проверки несовместимого выбора;
- частоты 400/2000 кГц;
- X по номеру кадра или температуре;
- быстрые пресеты:
  - `Амплитуды R1`;
  - `Амплитуды R2`;
  - `Отн. ампл.`;
  - `Разн. фаз`;
  - УЭС на приборе/компьютере;
  - симметричные фазы на приборе/компьютере;
  - `Ампл. молч.`;
  - `Разн. фаз молч.`;
  - `Температура`;
- актуальная компоновка подтверждена владельцем:
  - заголовок «Схема прибора» центрирован;
  - блоки кривых и быстрых пресетов имеют равную ширину;
  - частота выровнена слева, правая граница X-axis совпадает с `Амплитуды R2`;
  - `Применить` и `Отмена` находятся в раздельных равных колонках и не
    пересекаются при DPI-масштабировании;
  - `Температура` занимает всю ширину области быстрых пресетов;
  - красная диагностическая подпись удалена, но недопустимая конфигурация всё
    ещё блокирует `Применить`.

### COM и окно подключения

- поиск доступных COM-портов;
- transport 125000/8N1, DTR/RTS, таймауты и автоматическое переподключение;
- пакет `[CMD:1][LEN:2][PAYLOAD][CRC16:2]`;
- реализованы чтения `0x11` (кадр), `0x13` (метрология), `0x16` (signature);
- polling с интервалом 500–30000 мс;
- создание canonical `.bin` и дозапись существующего файла;
- параметры хранятся в
  `%LOCALAPPDATA%\AMK-Data-Visualization\connection-settings.json`;
- пункт «Настройки подключения» открывает окно одним кликом без промежуточного
  flyout;
- окно повторяет старую структуру: COM-порт, статус, запись в файл, таймер,
  `Подключить`/`Отключить`/`Закрыть`;
- текущий фиксированный размер окна: 600×680;
- визуальная структура окна подтверждена владельцем.

## Реализовано частично или является заглушкой

- `AMK.DataVisualization.Metrology` пока содержит только `.csproj`;
- `AMK.DataVisualization.Reporting` пока содержит только `.csproj`;
- `SmtComputationMode.FromComputer` присутствует в модели и UI, но
  `ChartDataCalculator` пока читает phase/rho из canonical полей прибора и не
  выполняет метрологический расчёт на компьютере;
- кнопки диапазона, reset/zoom/cut и cursor-поля присутствуют в shell, но
  соответствующая интерактивная логика не перенесена;
- `Поток` и его числовое поле пока не реализуют старый Surf-сценарий;
- controls заметок присутствуют визуально, но notes storage/rendering/hit-test
  не перенесены;
- пункты меню `Метрология`, `Конструктор файлов`, `Логи`,
  `Проверить обновления`, `Документация` в основном являются заглушками.

## Что требует ручной проверки

### Реальные файлы

- загрузка `.bin`, `.biv`, `.DEV` через WinUI picker;
- все пресеты Graph 1 и Graph 2 на одинаковом контрольном файле;
- комбинированные конфигурации с одной и двумя Y-осями;
- подписи легенды, сетка и числовые шкалы;
- X по температуре;
- capability-aware доступность T1..T5;
- linked/independent Graph 2 с двумя разными файлами;
- range export и cut range.

### Физический прибор

- подключение и отключение;
- чтение signature и метрологии;
- получение кадров, пауза и возобновление polling;
- восстановление после временного сбоя порта;
- создание нового `.bin`;
- дозапись существующего `.bin`;
- режим «Показывать весь файл» при дозаписи.

## Неперенесённые блоки

1. Метрология и формулы `from_computer`, включая решение по T5.
2. Остальные serial-команды (`0x12`, `0x17`, `0x1a`), selected key и air calibration.
3. `DeviceExchangeLog` и окно лога.
4. Zoom, scroll, undo/reset, crosshair, координаты курсора, LOD/cache.
5. Заметки и sidecar-сегменты.
6. Конструктор файлов.
7. Reporting/export/print.
8. Installer, versioning и auto-update.

## Решения, которые нельзя потерять

- Старый C++ проект — источник истины; улучшения поведения обсуждаются отдельно
  от переноса.
- `Core` владеет binary layout и adapter-driven parsing.
- `IO` читает контейнеры, но не дублирует расшифровку canonical payload.
- Graph 1 и Graph 2 имеют независимые `ChartConfiguration`.
- Graph 2 получает repository только через `ChartWorkspace`.
- Окно схемы немодальное и хранит отдельную незавершённую editor-сессию для
  каждого графика.
- Автоматизированные тесты не восстанавливать без прямого запроса владельца.
- Build success не называть runtime- или parity-проверкой.
