# AMK Data Visualization — оперативный снимок

Последнее обновление: **22 июля 2026 года**.

## Как начинать новую сессию

1. Выполнить `git status --short` и сохранить все пользовательские изменения.
2. Прочитать этот файл полностью.
3. Открыть `AMK_DATA_VISUALIZATION_MIGRATION_HANDOFF.md` для подробных
   контрактов затронутой вертикали.
4. Перед переносом legacy-поведения проверить соответствующие функции в
   `C:\Users\Admin\Desktop\Amk-Horizon-New-Chart`.
5. Не считать успешную сборку runtime- или parity-проверкой.

## Технический профиль

- WinUI 3 / .NET 10 / Windows App SDK 2.2;
- x64, unpackaged, self-contained;
- пользовательское имя «Визуализация данных»;
- executable `DataVisualization.exe`;
- версия в `.csproj` — `0.1.2`;
- all-users installer Inno Setup 6;
- автоматизированных тестовых проектов нет;
- приложение по просьбе владельца обычно не запускается: выполняется
  compile-only проверка, а UI тестирует владелец.

## Важное состояние релиза

`DataVisualization-Setup-0.1.2.exe` и
`data-visualization-version.txt` были успешно созданы, а SHA-256 descriptor
совпал с setup. После этого в исходники внесены новые изменения интерфейса и
окон. Следовательно, setup `0.1.2` не содержит текущее состояние кода.

Перед следующей публикацией необходимо:

1. назначить новый номер версии;
2. обновить `Version`, `AssemblyVersion`, `FileVersion` и
   `InformationalVersion` в `.csproj`;
3. повторно выполнить `scripts\Build-Installer.ps1`;
4. вручную проверить setup и только затем заменить setup и descriptor на
   сервере.

Не следует повторно публиковать изменённую сборку под уже выпущенным номером
`0.1.2`.

## Текущий функционал

- чтение `.bin/.biv/.DEV`, canonical repository и metadata;
- Graph 1/Graph 2 с отдельными конфигурациями и linked/independent источником;
- multi-series, одна/две Y-оси, X по кадрам или температуре;
- X Range, drag-zoom, undo/reset, X/Y-scroll, `Поток` и автоматический Y-fit;
- crosshair, координаты, сброс, перенос X в границы диапазона и контекстное
  создание заметки;
- legacy-совместимые заметки `.notes.jsonl`, маркеры, редактирование, удаление
  и журнал с восстановлением конфигурации;
- кнопка «Заметки» напрямую открывает журнал;
- сохранение/вырезание диапазона Graph 1 и append-варианты;
- конструктор файлов и segment-layout в `%LOCALAPPDATA%`;
- COM polling, reconnect, canonical recording и окно подключения;
- legacy-совместимое окно «Логи»: обычный/raw-режим, очистка, копирование,
  идентификация зонда и расшифровка `GP_TOOL_DATA`;
- единый поток из 300 последних элементов в окне и до трёх файлов сессий в
  `%LOCALAPPDATA%\AMK-Data-Visualization\Logs` с лимитом 32 МБ на файл;
- базовая ветка `Картограф LWD 4tx` с Q12-нормализацией;
- окно метрологии, 240-байтовые файлы и расчёт `FromComputer`;
- ручная и фоновая проверка обновлений через legacy HTTP-каталог;
- системные иконки папок для Graph 2 и статусной строки;
- открытие папки файла/COM-записи; в независимом двухфайловом режиме — выбор
  Graph 1 или Graph 2;
- окна подключения, конструктора, заметок, логов и метрологии имеют taskbar-кнопки,
  наследуют иконку приложения, восстанавливаются и центрируются над главным
  окном.

Недавние UI-сценарии, включая заметки, папки и вспомогательные окна,
подтверждены владельцем.

## Не считать завершённым

- полный parity всех кривых и пресетов на контрольных `.bin/.biv/.DEV`;
- численный parity `FromSonde` / `FromComputer`;
- полный COM reconnect и весь набор метрологических команд на физическом
  приборе;
- ручная проверка range save/cut/append и конструктора на всех форматах;
- LOD/downsampling, cache и единая geometry-модель;
- встроенная документация;
- reporting, печать и экспорт;
- code signing и полный install/update/uninstall release-цикл.

## Актуальный контракт логирования

`DeviceProtocolLog` направляет подробную transport-трассировку только в файл, а
raw-режим окна содержит legacy-совместимые TX-пакеты и расшифровку кадров. В
памяти остаются последние 300 элементов без визуального разделения на сессии.
В `%LOCALAPPDATA%\AMK-Data-Visualization\Logs` хранятся три последних файла
сессий размером до 32 МБ каждый; четвёртая сессия удаляет самый старый файл.
Ограниченная файловая очередь и инкрементальное обновление UI не блокируют
COM-поток и сохраняют выбранный пользователем диапазон прокрутки.
