# Функциональность приложения «Визуализация данных»

Документ описывает всё, что приложение умеет делать, с точки зрения
пользователя и с указанием реализующих файлов.

## Источник истины

Поведение прибора — команды, формат пакетов, единицы величин, расчёты на борту —
описывают прошивки в корне проекта:

```text
main_LWD_1DDS      — прошивка приборов LWD
main_AUTO_5Tx.txt  — прошивка автономных приборов
```

Всё, что касается обмена с прибором и смысла принятых значений, проверяется по
ним. Додумывать контракт нельзя: ошибка в единицах или смещениях даёт
правдоподобный, но неверный результат.

Прошивок нового поколения (кадр 320 байт) пока нет; до их получения источник
истины по новой ветке — отладочный проект `TEST_KARTOGRAF_2.0-main`.

## Два поколения приборов

Приложение работает и со старыми приборами, и с перепрошитыми:

| | Старая прошивка | Новая прошивка |
| --- | --- | --- |
| Кадр измерений | 240 байт | 320 байт |
| Метрология | 240 байт | 240 байт |
| Амплитудное УЭС и затухание | нет | есть |
| Воздушная поправка затухания | нет | есть |

Поколение определяется по сигнатуре прибора автоматически, отдельной настройки
нет. Возможности, которых у источника нет, в интерфейсе недоступны: пункты меню
и поля остаются на месте, но погашены — состав окон не меняется под руками.

## 1. Файлы данных

### 1.1. Открытие

Главное меню → «Файл» → «Открыть файл данных...». Поддерживаются три
контейнера: `.bin`, `.biv` и `.DEV`, каждый — от прибора любого поколения. Все
они приводятся к единому кадру измерений; различается размер физической записи в
файле (см. [`DATA_FORMATS.md`](DATA_FORMATS.md)).

При открытии определяется тип прибора по сигнатуре первого кадра, из неё же
выводятся число передатчиков, поколение прошивки и возможности источника. Размер
записи, полученный из сигнатуры, подтверждается по самому файлу; если не
подтвердился ни один известный размер, файл отклоняется с явным сообщением, а не
читается наугад. Имя файла и число кадров
показываются в строке состояния.

### 1.2. Неполные и повреждённые данные

Дамп памяти прибора обрывается там, где остановилась запись, поэтому последняя
запись в файле регулярно неполная. Приложение это учитывает:

- отказ в открытии происходит только тогда, когда в файле нет ни одного полного
  кадра;
- неполный хвост пропускается, его длина считается;
- кадр, не прошедший разбор, пропускается и считается отдельно — одна
  повреждённая запись в середине длинной записи не стоит пользователю всего
  файла;
- правило одинаково работает для всех трёх контейнеров.

Если что-то было пропущено, после открытия выводится сводка «Файл открыт с
замечаниями» с числом повреждённых кадров и размером оборванного хвоста. Если
файл открыть не удалось, показывается конкретная причина отказа, а не пустой
график.

Реализация: `ToolDataFileReader`, `ToolDataRepository`,
`MainWindow.ReportFileLoadIssuesAsync`.

### 1.3. Операции с диапазоном

Для первого графика доступны:

- сохранение выбранного диапазона в новый файл `.bin`;
- вырезание выбранного диапазона из текущего файла;
- сохранение копии файла без выбранного диапазона с сохранением исходного
  физического формата;
- дозапись выбранного диапазона или файла без вырезаемого диапазона в
  существующий совместимый файл `.bin`.

Реализация: `ToolDataRangeExporter`.

### 1.4. Конструктор файлов

Главное меню → «Конструктор файлов». Объединяет несколько совместимых файлов
`.bin`, `.biv` и `.DEV` в один файл `.bin`:

- проверяет совместимость сигнатур объединяемых файлов, а значит и совпадение
  поколения прошивки: файлы с кадрами 240 и 320 байт не объединяются;
- позволяет менять порядок сегментов;
- позволяет открыть ранее собранный файл и пересохранить сборку.

Границы исходных сегментов запоминаются и рисуются на графике пунктиром — видно,
где заканчивается один исходный файл и начинается другой. Описание сегментов
переносится при вырезании диапазона.

Реализация: `ToolDataFileConstructor`, `FileConstructorWindow`.

## 2. Графики

### 2.1. Два графика и источники данных

Флажок «Двойной режим» включает второй график. У каждого графика собственная
конфигурация кривых и собственное состояние просмотра — диапазон, масштаб,
история отмены.

Второй график работает в одном из двух режимов:

- **связанный** — читает те же данные, что и первый;
- **отдельный файл** — имеет собственный файл, открываемый кнопкой с иконкой
  папки на его панели.

Переключение режима не очищает первый график и не удаляет уже открытый файл
второго.

### 2.2. Кривые

Виды данных, доступные для вывода:

| Вид | Смысл |
| --- | --- |
| разность фаз | разность фаз между приёмниками |
| отношение амплитуд | отношение амплитуд приёмников |
| амплитуда R1, амплитуда R2 | амплитуда соответствующего приёмника |
| симметризованная фаза | фаза после симметризации |
| УЭС | удельное электрическое сопротивление по фазе |
| УЭС по затуханию | амплитудное УЭС в Ohm*m, только новая прошивка |
| затухание | симметризованное затухание в dB, только новая прошивка |
| молчащие каналы | амплитуды R1/R2 и разность фаз молчащего передатчика |
| температура | температура прибора |

Каждая кривая привязана к передатчику (T1–T5) и частоте (400 или 2000 кГц),
имеет свой цвет, единицы измерения и группу оси Y.

Симметризованная фаза, УЭС, УЭС по затуханию и затухание считаются в двух
режимах: значения, пришедшие от прибора, и расчёт на стороне приложения. Второй
режим доступен только после успешного чтения метрологии.

Кривые по затуханию доступны только для источника новой прошивки. Конфигурация,
построенная для такого прибора, при переходе на источник старой теряет их до
отрисовки — иначе они остались бы в легенде без данных.

### 2.3. Выбор кривых: окно «Настройка кривых»

Кнопка «Настройка кривых» открывает немодальное окно со схемой прибора. В нём:

- выбираются передатчики T1–T5, приёмники R1/R2 и молчащие каналы;
- выбирается частота 400 или 2000 кГц;
- выбирается ось X — номер кадра или температура;
- применяются быстрые пресеты: амплитуды R1, амплитуды R2, отношения амплитуд,
  разности фаз, молчащие амплитуды, молчащая разность фаз, температура, УЭС,
  симметризованные фазы, а для приборов новой прошивки — УЭС по затуханию и
  затухание. Блоки «УЭС по затуханию» и «Затухание» стоят отдельным рядом под
  «УЭС» и «Симм. фазы» и недоступны для источника старой прошивки;
- блокируются несовместимые сочетания элементов.

Окно ведёт отдельное состояние для каждого графика и переиспользует уже
открытый экземпляр.

Доступные элементы определяются возможностями источника: если загружен прибор с
четырьмя передатчиками, T5 недоступен и кривые T5 не выводятся.

### 2.4. Выбор кривых прямо на графике

У подписи каждого графика есть кнопка-иконка «ключ с шестерёнкой». Она открывает
меню из четырёх опций вывода:

1. список быстрых пресетов на графике;
2. выбор частоты в левом углу графика;
3. схема прибора сверху графика;
4. выбор оси X в панели управления графиком.

Списки пресетов и частоты располагаются в одну линию справа от шестерёнки,
компактная схема — по центру верхней границы графика. Выпадающие списки без
заголовка показывают текущее значение и подстраивают ширину под него. Частота по
умолчанию 400 кГц, её смена сразу переприменяет текущий выбор.

Список пресетов разделён на два раздела с заголовками — «Фазовые измерения» и
«Амплитудные измерения». Деление идёт по природе измеряемой величины, поэтому
УЭС относится к фазовым (прибор считает его из разности фаз), а УЭС по затуханию
— к амплитудным. Внутри разделов порядок одинаков: сырая величина, молчащие
каналы, симметризованная величина, УЭС. Температура не относится ни к одному
разделу и стоит отдельно в конце.

Быстрые пресеты и выбор на схеме — независимые ветви: пока активен быстрый
пресет, элементы схемы не подсвечиваются. У компактной схемы есть собственная
кнопка «Применить», появляющаяся при наличии несохранённого изменения.

Когда включён список пресетов или схема, в конце легенды появляется
кнопка-«глаз»: она показывает и скрывает отдельные кривые уже применённой
конфигурации.

Схема подсвечивает элементы только для той конфигурации, которую построила сама
эта поверхность. Комбинированный выбор нельзя однозначно восстановить из списка
кривых, поэтому конфигурация из окна не подсвечивается на графике и наоборот.

Выбор четырёх опций сохраняется на диск отдельно для каждого графика.

Реализация: `MainWindow`, `LineChartControl`, `InlineSchematicBar`,
`ChartDisplaySettingsStore`.

### 2.5. Оси, масштаб и прокрутка

- диапазон по X задаётся полями «от» и «до»; пустое «до» означает последнюю
  запись;
- масштабирование выделением области мышью по обеим осям;
- пошаговая отмена масштабирования кнопкой `↶` и полный сброс;
- отдельные кнопки `−` у горизонтальной и вертикальной полос прокрутки отменяют
  шаг масштабирования только по своей оси;
- при двух осях Y список «Zoom оси Y» задаёт цель масштабирования: обе оси,
  только левая или только правая. Нецелевая ось остаётся на своём диапазоне, и
  вертикальная прокрутка двигает только выбранную;
- горизонтальная и вертикальная прокрутка увеличенного участка;
- при горизонтальной прокрутке автоматический диапазон Y пересчитывается под
  новый видимый участок, а вручную заданное окно Y сохраняет свою высоту;
- к автоматическому диапазону Y добавляется отступ 5 % от экстремумов;
- шаг сетки и формат подписей выбираются по «круглым» значениям.

### 2.6. Режим «Поток»

Показывает последние N записей и следует за поступающими живыми данными. Ручное
изменение диапазона X при этом заблокировано, а масштабирование и прокрутка по Y
остаются доступными.

## 3. Заметки на графике

- заметки хранятся рядом с активным файлом данных в файле
  `<файл-данных>.notes.jsonl`; для работы с прибором файл создаётся только при
  включённой записи;
- клик по графику ставит красное перекрестие и заполняет поля координат курсора;
  при двух осях Y показываются координаты обеих осей;
- кнопка `⌖` сбрасывает перекрестие и координаты;
- правый клик по графику позволяет перенести позицию перекрестия в начальную или
  конечную границу диапазона X либо создать заметку;
- маркеры заметок показываются только при совпадающей оси X и включённых
  кривых с их группами осей Y; конкретный пресет в сопоставление не входит;
- клик по маркеру позволяет изменить или удалить заметку;
- кнопка «Заметки» открывает журнал заметок, из которого можно изменить текст и
  восстановить сохранённую конфигурацию кривых;
- для второго графика в режиме отдельного файла заметки не создаются и не
  показываются.

Реализация: `NotesModule`, `NotesJournalWindow`.

## 4. Работа с прибором

### 4.1. Подключение

Главное меню → «Настройки подключения». Окно показывает доступные COM-порты,
позволяет выбрать порт, интервал опроса, включить запись и выбрать её каталог.

Параметры обмена: 125000 бод, 8 бит, без чётности, один стоп-бит, без
аппаратного управления потоком. Подробности — в
[`DEVICE_PROTOCOL.md`](DEVICE_PROTOCOL.md).

Выбранный порт запоминается между сессиями и остаётся выбранным по умолчанию
даже тогда, когда прибор к нему ещё не подключён: автоматическая подмена на
«первый доступный» не выполняется. При попытке включения на недоступном порту
выводится поясняющее сообщение и открывается окно подключения.

Интервал опроса между сессиями не запоминается: каждая сессия стартует с
2000 мс. Минимально допустимое значение — 700 мс, ниже прибор не успевает
отдавать кадры.

### 4.2. Опрос и восстановление связи

Кнопка «Включить» в главном окне запускает обмен. Принятые кадры добавляются в
хранилище и сразу выводятся на график. После восьми отказов подряд порт
закрывается и открывается заново.

Транспорт обмена выбирается автоматически по ответу прибора, а не настройкой
пользователя. Приборы `Картограф` с четырьмя передатчиками работают по
транспорту фиксированной длины, остальные — по транспорту с полем длины.

### 4.3. Запись живых кадров

Кадры пишутся подряд в новый файл `.bin` либо дозаписываются в существующий —
ровно в том размере, в каком их отдал прибор: по 240 байт от старой прошивки, по
320 от новой. Дозапись возможна только в файл того же поколения. Имя нового файла формируется из номера корпуса, диаметра зонда и
времени начала записи.

Каталог записи по умолчанию — `Рабочий стол\AMK_Data`, он создаётся
автоматически. Другой выбранный путь запоминается между сессиями. Кнопка с
системной иконкой папки в строке состояния открывает текущий каталог записи или
каталог открытого файла; при двух независимых файлах предлагается выбрать, какой
из них открыть.

### 4.4. Журнал обмена

Главное меню → «Логи». Окно показывает обмен с прибором в обычном и «сыром»
режимах, расшифровывает принятые кадры, выделяет блок идентификации зонда,
позволяет очистить память, приостановить запись, скопировать содержимое и
открыть каталог журналов.

В памяти хранятся последние 300 записей единым потоком. На диске остаются три
последних файла сессий размером до 32 МБ каждый; при создании четвёртой сессии
самый старый файл удаляется. Запись выполняется вне потоков обмена и интерфейса,
поэтому не тормозит опрос.

Подробная транспортная трассировка пишется только в файл; в окно попадает состав,
достаточный для разбора обмена глазами.

## 5. Метрология

Главное меню → «Метрология». Немодальное окно с параметрами прибора.

### 5.1. Состав окна

- **Геометрия зонда** — L1 и L2 по каждому передатчику, частоты F1 и F2. По
  умолчанию доступны только для чтения; флажок «L/F только для чтения»
  разрешает редактирование;
- **Воздушные калибровки** — поправка фазы и порог амплитуды по каждому
  передатчику для обеих частот, сигнатура прибора в двоичном виде и палитра;
- **Идентификация зонда** — тип прибора, число передатчиков, модификация,
  серийный номер прибора («Серийный №»), номер корпуса («Корпус №»), положение
  приёмника R1 и поколение прошивки с размером кадра.

Поле «Прошивка» показывает поколение прибора и размер его кадра. Звёздочка в
нём означает, что метрология в приборе не размечена — её сигнатура прибор не
опознаёт — и идентификация взята из принимаемых кадров; подсказка поля поясняет
это. Кнопка «Записать в зонд» в таком случае занесёт в прибор корректную
сигнатуру.

Для приборов новой прошивки в блоке воздушных калибровок доступны ещё две
колонки — воздушная поправка затухания по каждой частоте. Для старых приборов
они погашены и пусты: по этим смещениям у старой метрологии служебная область,
смысл которой приложению неизвестен, и ни показывать её как калибровку, ни
писать туда нельзя.

### 5.2. Операции

- **Считать из зонда** — чтение метрологии с прибора;
- **Записать в зонд** — запись метрологии с последующим перечитыванием и
  сверкой сигнатуры и номера корпуса;
Нижние ряды кнопок занимают всю ширину окна: «Считать из зонда», «Записать в
зонд», «Открыть файл», «Сохранить файл», а под ними «Автокалибровка нулей
воздуха» и «Загрузить в базу данных». Отдельной кнопки закрытия нет — окно
закрывается системной кнопкой заголовка, как остальные немодальные окна.

- **Открыть файл** и **Сохранить файл** — работа с 240-байтовым файлом
  метрологии; при открытии проверяется поддерживаемость сигнатуры;
- **Автокалибровка нулей воздуха** — команда прибору пересчитать нули воздуха.

Запись метрологии уходит той командой, которую понимает подключённый прибор:
старая прошивка — `0x13`, новая — `0x12`. Выбор делает приложение по сигнатуре;
команда, которой у прибора нет, не отправляется.

### 5.3. Автокалибровка нулей воздуха

Прибор пересчитывает поправки `Air_zz` из собственного скользящего среднего
разности фаз, записывает метрологию в свою энергонезависимую память и отвечает
квитанцией. Поддерживаются оба транспорта обмена, включая режим
`Картограф LWD 4tx`.

Перед отправкой опрос ставится на паузу. После успешного выполнения приложение
предлагает перечитать метрологию: новые нули воздуха находятся в приборе, а не в
копии, которую держит окно.

Прошивка усредняет фиксированное число измерений, поэтому калибровка,
запущенная сразу после подключения, опирается на неполное окно усреднения.

### 5.4. Расчёты

Реализованы воздушная поправка, разбор байта состояния, матрицы симметризации
для 3, 4 и 5 передатчиков, вычисление сигнала, обратный расчёт УЭС и
симметризованные фазы.

Для приборов новой прошивки добавлена амплитудная ветка: затухание между
приёмниками в децибелах, приведение к воздуху по `air_att_dB`, симметризация той
же матрицей и обратный расчёт амплитудного УЭС. Формулы и границы поиска —
в [`DEVICE_PROTOCOL.md`](DEVICE_PROTOCOL.md). Режим расчёта на стороне приложения блокируется до
успешного чтения метрологии; при несовпадении сигнатуры выполняется возврат к
значениям, пришедшим от прибора.

Реализация: `MetrologySession`, `MetrologyCalculator`, `MetrologyWindow`.

## 6. Загрузка файлов в базу учёта приборов

Приложение загружает файлы прибора прямо в его карточку на сайте учёта, без
ручного выбора файла в браузере.

### 6.1. Настройка связи

Главное меню → «Связь с БД».

Порядок первоначальной настройки:

1. на сайте учёта приборов войти под своей учётной записью;
2. открыть «Профиль» и нажать «Создать токен»;
3. скопировать показанный токен — второй раз он не показывается;
4. в приложении открыть «Связь с БД», вставить токен и нажать «Сохранить».

Кнопка «Проверить соединение» запрашивает у сервера имя пользователя и
показывает его: сразу видно, под чьей учётной записью пойдут загрузки.

Токен сохраняется в профиле пользователя Windows и используется во всех
последующих сессиях — создавать его заново не нужно. На диск он попадает
зашифрованным средствами Windows: файл настроек, скопированный на другой
компьютер, расшифровать нельзя. Кнопка «Удалить токен» отключает загрузку.

### 6.2. Определение прибора

Файл попадает в карточку прибора по трём признакам: серийный номер, номер
корпуса и тип.

**Серийный номер прибора берётся из сигнатуры** — это поле «Серийный №» окна
метрологии, и именно оно совпадает с полем `serial_number` карточки прибора на
сайте. Поле «Корпус №» того же окна (`Serial` структуры метрологии) содержит
номер корпуса и в поиске прибора не участвует.

Это поле закодировано в сигнатуре прибора вместе с типом и числом передатчиков:

```text
низшие 20 бит сигнатуры = код прибора * 1000 + номер
0x00024FCE → 151502 → Автономный, 5 передатчиков, модификация 1, номер 502
```

Практическое следствие: **любой файл описывает свой прибор сам**. Сигнатура есть
и в метрологии, и в каждом кадре измерений, поэтому серийный номер известен
всегда — и при загрузке метрологии, и при загрузке ранее записанного файла
данных без подключённого прибора.

**Номер корпуса приложение не подставляет само** — в приборе его нет. Если
взять его наугад, файл попадёт в базу под несуществующим сочетанием и на сайте
виден не будет. Номер корпуса приходит только в ответе сервера.

Расхождения типа или числа передатчиков между прибором и карточкой показываются
предупреждением, но загрузку не запрещают.

### 6.3. Если прибора нет в базе

Отсутствие карточки — рабочая ситуация: её могли не завести или завести с другим
номером. Поэтому загрузка не прерывается сообщением об ошибке.

Приложение запрашивает у сервера **все приборы того же типа и с тем же числом
передатчиков** и показывает их списком с пояснением: прибор с таким серийным
номером в базе отсутствует, возможно, карточка не была создана; если в списке нет
подходящего прибора — создайте карточку на сайте (адрес выводится ссылкой).

Пользователь либо выбирает нужный прибор из списка, либо отменяет загрузку и
заводит карточку.

Если приборов такого типа в базе нет вовсе, выводится сообщение с предложением
создать карточку.

Отдельный случай — несколько приборов с одним серийным номером: это расхождение в
самой базе, и выбор в таком случае делает пользователь, а не приложение.

### 6.4. Метрология и калибровка

Окно «МЕТРОЛОГИЯ» → «Загрузить в базу данных» (кнопка занимает правую половину
нижнего ряда, рядом с «Автокалибровкой нулей воздуха»).

Раздел карточки прибора зависит от того, откуда взята метрология.

**Метрология считана из зонда.** Раздел определяет приложение, выбор не
предлагается:

| Состояние | Раздел |
| --- | --- |
| автокалибровка в этой сессии не выполнялась | «Метрология» |
| автокалибровка выполнена и метрология перечитана | «Калибровка» |

Приложение само знает, выполнялась ли калибровка, поэтому вопрос пользователю
ничего не добавил бы, а ошибиться позволил бы.

**Метрология открыта из файла.** Приложение выводит выбор между «Метрология» и
«Калибровка» — по содержимому файла отличить одно от другого нельзя, это знает
только пользователь. По умолчанию предлагается «Метрология».

Признак калибровки снимается при открытии файла: он относится к калибровке,
выполненной этим приложением, и не должен переноситься на содержимое файла
неизвестного происхождения.

Загружаются те же 240 байт, что записывает кнопка «Сохранить файл». Кнопка
доступна и без подключённого прибора, если метрология открыта из файла.

### 6.5. Термопрофиль и КИС

Главное меню → «Файл» → «Загрузить в базу данных». Пункт появляется только
тогда, когда есть что загружать: открыт файл данных или идёт запись через
COM-порт. Раздел выбирается в диалоге: «Термопрофиль | Воздух» или «КИС».
Нагрев и подвес на воздухе не разделяются — на сайте это один раздел.

Во время активной записи файл выгружается прямо из-под записи. Содержимое
обрезается по границе кадра, поэтому в базу не попадает половина последней
записи, а в окне подтверждения указывается число выгруженных кадров. Кадры,
принятые после нажатия кнопки, в эту копию не войдут.

### 6.6. Имя файла и повторные загрузки

Имя предлагается по единому шаблону и остаётся редактируемым:

```text
metro_LWD_108(005-2024)_20260815_143012.bin
calib_Картограф_351002(005-2025)_20260815_143012.bin
thermo_LWD_108(005-2024)_20260815_143012.bin
kis_LWD_108(005-2024)_20260815_143012.bin
```

Сервер сверяет контрольную сумму загружаемого файла с уже имеющимися в этом
разделе карточки. Если такой файл уже загружен, приложение сообщает, когда это
произошло, и спрашивает, нужна ли ещё одна копия. Повторное нажатие кнопки
поэтому безопасно.

Через приложение загружаются только файлы данных прибора: `.bin`, `.biv` и
`.DEV`. Отчёты и документы по-прежнему загружаются на сайте.

## 7. Окна и оформление

- окна подключения, конструктора файлов, журнала заметок, логов, метрологии и
  масштаба немодальные, имеют собственные кнопки в панели задач, наследуют
  иконку приложения, центрируются относительно главного окна при первом и
  повторном открытии и корректно восстанавливаются после сворачивания;
- главное окно нельзя сжать меньше 90 % ширины и 80 % высоты того монитора, на
  котором оно находится: иначе панели управления и два графика не помещаются.
  Предел пересчитывается при переносе окна на другой монитор;
- приложение всегда открывается в светлой теме и использует фиксированную синюю
  палитру акцента независимо от темы и акцентного цвета Windows. График рисуется
  фиксированными светлыми цветами, и на тёмном фоне он был бы нечитаем. В
  высококонтрастном режиме системные цвета сохраняются;
- кнопка «Масштаб окна» задаёт масштаб содержимого всех окон приложения.
  Компоновка рассчитана на 1536×864 аппаратно-независимых пикселя, и на большом
  мониторе элементы иначе выглядят мелкими. Выбор сохраняется между сессиями.
  Выпадающие меню и системные диалоги остаются в системном размере.

Реализация: `SecondaryWindowIntegration`, `MinimumWindowSize`,
`WindowScaleService`, `App.xaml`.

## 8. Обновление и документация

- «Проверить обновления» выполняет проверку вручную; при запуске приложения
  через три секунды выполняется тихая фоновая проверка;
- новая версия скачивается во временный каталог и до запуска проверяется по
  имени файла, размеру, сигнатуре исполняемого файла и контрольной сумме
  SHA-256;
- после установки обновления приложение перезапускается;
- «Документация» открывает PDF документации в браузере по умолчанию.
  Встроенной документации внутри приложения нет.

Реализация: `AutoUpdateService`. Каталог обновлений и порядок публикации описаны
в [`../installer/README.md`](../installer/README.md).
