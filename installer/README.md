# Установщик «Визуализация данных»

Приложение распространяется как unpackaged WinUI 3, self-contained
`Release x64`. Установщик создаётся Inno Setup 6 и предназначен для всех
пользователей компьютера.

## Источник истины

Поведение прибора описывают его прошивки в корне проекта — `main_LWD_1DDS` и
`main_AUTO_5Tx.txt`. Это правило действует и здесь: если для проверки собранной
версии нужно понять, что именно приложение отправляет прибору или как
интерпретирует ответ, ответ берётся из прошивок, а не из предположений.

## Источник версии

Единственный источник номера версии:

```text
AMK-Data-Visualization\AMK-Data-Visualization.csproj -> Version
```

`scripts\Build-Installer.ps1` передаёт это значение Inno Setup и создаёт:

```text
installer\Output\DataVisualization-Setup-<version>.exe
installer\Output\data-visualization-version.txt
```

Дублировать номер версии вручную в инструкциях или в файле обновлений не следует.

## Правило номеров версий

Нельзя публиковать другое содержимое под уже использованным номером: клиент
обновления сравнивает версии и может не загрузить такую замену. Если после
сборки установщика в дерево исходников попала хотя бы одна правка, нужен новый
номер и пересборка.

Текущее состояние: `DataVisualization-Setup-0.2.2.exe` и descriptor собраны
25 августа 2026 года из текущего дерева исходников.

- размер setup — 62 358 645 байт;
- SHA-256 — `8FF19F56…D3811F93`, совпадает с независимо пересчитанным хэшем;
- версия исполняемого файла в payload — `0.2.2.0`;
- descriptor указывает на фактическое имя установщика и содержит этот же хэш;
- в payload проверено наличие кода этой версии: `ResizeClientToContent` и
  `ContentCanvas` в `DataVisualization.dll`; `CaptureSessionRecordingChoice` и
  `ApplySessionRecordingChoice` в `AMK.DataVisualization.Hardware.dll`;
  `ToolSignature`, `FirmwareGeneration`, `GetRhoAttSmt` и `GetAirAttDb` в
  `AMK.DataVisualization.Core.dll`; `TryCalculateAttDbSmt` и
  `InvertAttenuationToRho` в `AMK.DataVisualization.Metrology.dll`;
  `CommandMetrologyWrite` и `ResolvedDeviceSignature` в
  `AMK.DataVisualization.Hardware.dll`; `RhoAttSmt` и `AttDbSmt` в
  `AMK.DataVisualization.Charting.dll`;
- в payload лежат `XBF` всех одиннадцати существующих окон — ровно те, что
  перечислены в обязательном списке скрипта сборки.

Что изменилось по версиям: `0.2.0` добавила поддержку приборов с новой прошивкой
(кадр 320 байт); `0.2.1` меняла размер окна метрологии и сделала это неверно —
требуемый размер задан в аппаратно-независимых пикселях, а `ResizeClient`
принимает физические, поэтому на дисплее со 125 % окно выходило на пятую часть
меньше содержимого и обрезало колонки воздушных поправок затухания вместе с
обоими рядами кнопок. `0.2.2` переводит требуемый размер по DPI монитора и
дополнительно убирает сохранение дозаписи в существующий файл между сессиями.

`0.2.0` в каталог обновлений не публиковалась. Установщики `0.1.1`…`0.2.1`
остались в `installer\Output` как история; в каталог обновлений публиковались не
все.

Приложение этой версии проверено владельцем на сборке из дерева исходников: окно
метрологии показывается целиком, выбранная дозапись не переносится в новую
сессию. Сам установщик при упаковке не запускался. Публикация в каталог
обновлений и проверка установки остаются за владельцем.

## Сборка

Из корня репозитория:

```bash
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./scripts/Build-Installer.ps1
```

Скрипт:

1. очищает изолированные `artifacts\build\win-x64` и `artifacts\publish\win-x64`;
2. выполняет self-contained `dotnet publish` для `Release|x64`;
3. переносит созданные WinUI `DataVisualization.pri` и `*.xbf` из каталога
   сборки в каталог публикации;
4. проверяет исполняемый файл, `runtimeconfig`, `PRI` и перечисленные в скрипте
   обязательные `XBF` окон, библиотеки `Microsoft.UI.Xaml` и загрузчик Windows
   App Runtime;
5. компилирует установщик;
6. вычисляет SHA-256 и записывает файл описания обновления.

При отсутствии любого обязательного файла сборка прерывается до создания
установщика — заведомо неполный setup не создаётся. Параметр `-SkipPublish`
допустим только для повторной компиляции уже проверенного каталога публикации.

## Поведение установки

- требуется подтверждение UAC;
- каталог по умолчанию — `Program Files\Визуализация данных`;
- приложение регистрируется в «Установленных приложениях»;
- пользователь отдельно выбирает общие ярлыки меню «Пуск» и рабочего стола;
- стабильный идентификатор приложения позволяет устанавливать новую версию
  поверх существующей;
- после обычной установки мастер предлагает запустить приложение;
- удаление выполняется стандартным деинсталлятором Inno Setup.

## Публикация обновлений

Каталог обновлений:

```text
http://ivanbohg.beget.tech/FilesForProgramVisualisation/
```

В него публикуются установщик и файл описания `data-visualization-version.txt`:

```text
<версия>
DataVisualization-Setup-<версия>.exe
<SHA-256>
```

Первые две строки обязательны, третья рекомендуется и проверяется до запуска
установщика.

При старте приложение через три секунды выполняет тихую проверку обновлений.
Ручная проверка доступна из главного окна. Если версия новее, пользователь
подтверждает загрузку; файл скачивается во временный каталог, проверяется по
имени, размеру, сигнатуре исполняемого файла и SHA-256, затем запускается с UAC.
Режим `/UPDATE=1` перезапускает приложение после установки.

## Порядок выпуска

1. Задать номер версии в `.csproj`, убедившись, что он выше опубликованного и
   ранее не использовался для другого содержимого.
2. Собрать установщик штатным скриптом.
3. Убедиться, что файл описания указывает на фактическое имя установщика и
   содержит его SHA-256.
4. Убедиться, что список обязательных файлов в скрипте включает `XBF` каждого
   существующего окна.
5. Подписать `DataVisualization.exe` и установщик сертификатом.
6. Проверить установку поверх предыдущей версии, оба ярлыка, запуск, удаление и
   автообновление.
7. Опубликовать установщик и файл описания только после ручной проверки.

## Известные ограничения

Каталог обновлений работает по HTTP. SHA-256 защищает скачанный установщик от
незамеченной подмены только при доверенном файле описания и не заменяет HTTPS.
Код не подписан, поэтому Windows SmartScreen может показывать предупреждение.
Полный цикл установки, обновления и удаления между двумя опубликованными
подписанными версиями не проверялся.
